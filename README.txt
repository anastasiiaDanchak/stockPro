1. ВИМОГИ ДО СИСТЕМИ
----------------------------------------------------------------

Перед початком переконайтесь, що на вашому комп'ютері встановлено:

  - Docker Desktop  (версія 24 або новіша)
      Завантажити: https://www.docker.com/products/docker-desktop
  - Docker Compose  (входить до складу Docker Desktop)
  - Node.js 18+     (тільки для локального запуску фронтенду)
      Завантажити: https://nodejs.org
  - Git             (для клонування репозиторію)
      Завантажити: https://git-scm.com

Перевірка встановлення (відкрийте термінал / командний рядок):

  docker --version
  docker compose version
  node --version
  git --version


----------------------------------------------------------------
2. ВСТАНОВЛЕННЯ
----------------------------------------------------------------

Крок 1. Клонуйте репозиторій або розпакуйте архів проєкту:

  git clone <URL_репозиторію>
  cd StockPro

  Або, якщо маєте ZIP-архів:
    - Розпакуйте його в будь-яку зручну папку
    - Відкрийте термінал і перейдіть до папки StockPro:
        cd шлях/до/StockPro

Крок 2. Встановіть залежності фронтенду:

  cd frontend
  npm install
  cd ..


----------------------------------------------------------------
3. НАЛАШТУВАННЯ ЗМІННИХ СЕРЕДОВИЩА
----------------------------------------------------------------

У кореневій папці проєкту (там де docker-compose.yml) створіть
файл з назвою  .env  та додайте до нього такий вміст:

  JWT_SECRET=supersecretkey_stockpro_2024

Ви можете змінити значення JWT_SECRET на будь-який довгий
рядок — це секретний ключ для підпису токенів авторизації.

УВАГА: файл .env не треба передавати у Git (він вже є у .gitignore).

Щоб створити файл .env у терміналі:

  Windows (PowerShell):
    echo JWT_SECRET=supersecretkey_stockpro_2024 > .env

  Mac / Linux:
    echo "JWT_SECRET=supersecretkey_stockpro_2024" > .env

4. ЗАПУСК ЗАСТОСУНКУ
----------------------------------------------------------------

КРОК А: Запустіть бекенд (усі мікросервіси + бази даних)

  Перебуваючи в папці StockPro, виконайте:

    docker compose up --build

  При першому запуску Docker завантажить усі необхідні образи
  та збере контейнери — це може зайняти 3-7 хвилин.

  Коли у консолі з'являться повідомлення типу:
    "auth-service running on port 4001"
    "analytics-service running on port 3002"
    ...
  бекенд готовий до роботи.

  Якщо хочете запустити у фоновому режимі (без виводу логів):

    docker compose up --build -d

КРОК Б: Запустіть фронтенд (у новому вікні терміналу)

  cd frontend
  npm start

  Після цього у браузері автоматично відкриється адреса:
    http://localhost:3006

  Якщо не відкрилося — відкрийте вручну.

6. ЗУПИНКА ТА ОЧИЩЕННЯ
----------------------------------------------------------------

Зупинити всі контейнери (дані в базі зберігаються):

  docker compose down

Зупинити та повністю видалити дані (база буде очищена):

  docker compose down -v

Переглянути статус контейнерів:

  docker compose ps

Переглянути логи конкретного сервісу:

  docker compose logs auth-service
  docker compose logs analytics-service

8. ВИРІШЕННЯ ТИПОВИХ ПРОБЛЕМ
----------------------------------------------------------------

ПРОБЛЕМА: "Port is already in use" (порт зайнятий)
  Рішення: Зупиніть інший застосунок, що використовує цей порт,
  або перезапустіть Docker Desktop.

ПРОБЛЕМА: Сторінка не завантажується / "Cannot connect"
  Рішення:
    1. Переконайтесь, що Docker запущено
    2. Виконайте: docker compose ps
    3. Усі сервіси мають мати статус "running"
    4. Зачекайте 30-60 секунд після старту — сервісам потрібен
       час для з'єднання між собою

ПРОБЛЕМА: "Invalid token" або розлогінення при кожному запиті
  Рішення: Переконайтесь, що у файлі .env є JWT_SECRET,
  і перезапустіть Docker: docker compose restart

ПРОБЛЕМА: Порожня база даних / немає тестових користувачів
  Рішення: Дані завантажуються лише при першому запуску.
  Якщо база вже існує, виконайте:
    docker compose down -v
    docker compose up --build
  (УВАГА: це видалить усі дані)

ПРОБЛЕМА: Фронтенд не запускається (npm start)
  Рішення:
    cd frontend
    npm install   <- переконайтесь, що виконали цей крок
    npm start

ПРОБЛЕМА: "EACCES: permission denied" (Mac/Linux)
  Рішення: Не запускайте команди через sudo.
  Замість цього налаштуйте права Docker:
    sudo usermod -aG docker $USER
  Потім вийдіть із системи і зайдіть знову.
